# 设计决策记录

> 状态：从提供的 v0.1 原稿整理，日期 2026-10-27。区分设计约束、原稿建议与待定研究问题；不代表已经实现。

## 设计约束与名义目标

| ID | 决策 | 理由与影响 |
| --- | --- | --- |
| D01 | 基础块与局部更新宽度为 64 槽 | 统一 APPEND、EDIT 和 Decoder 读取的基本单位 |
| D02 | 工作矩阵动态增长，并允许覆盖已有 64 槽区间 | 联合验证连续状态的追加与纠错能力 |
| D03 | 保留 AR 文本 Decoder，潜在 Cross-Attention 每次只读 64 槽 | 明确局部潜在读取与 Token 自回归的边界；全矩阵另作对照 |
| D04 | 两个 Encoder 同档规模相同，默认不共享权重 | 输入条件和目标潜在空间职责不同；共享可作消融 |
| D05 | 推理不运行目标 `E_lat(y)` | `E_lat` 定义训练监督，部署期未知真实答案 |
| D06 | 详略联合使用步长、详细度标签与输出上限 | 窗口数量不能直接等同于有意义的输出长度 |
| D07 | 采用 S1–S5 的名义规模目标 | 精确层数和参数量需通过实际计数确定，详见[工程页](engineering.md) |

## 原稿的首版建议

| ID | 建议 | 何时重新评审 |
| --- | --- | --- |
| P01 | EDIT 先对齐 64 槽块边界 | 修复和定位稳定后，再比较任意跨块窗口 |
| P02 | 内部推理结束后固定矩阵，再解码 | 只有明确解决矩阵版本和输出一致性后，才研究边改边输出 |
| P03 | Decoder 不直接读输入条件 `C` | 完成矩阵依赖验证后，可单独增加条件旁路对照 |
| P04 | 学习 WRITE/ADVANCE；固定周期推进作基线 | 若推进学习不稳定，先在固定规则下检验读取质量 |
| P05 | 阶段 2 先冻结潜在空间；阶段 3 仅有限解冻 | 用分布漂移、任务质量和成本决定解冻范围 |
| P06 | DDPM 与 Flow 均做轻量比较 | 根据真实质量、采样步数和耗时选择后续方案 |
| P07 | 先 S1/S2，再 S3；S4/S5 等收益证据 | 依据预算匹配、多种子结果决定是否扩展 |

## 待定问题与验证方式

| ID | 问题 | 候选方案 | 决定所需证据 |
| --- | --- | --- | --- |
| Q01 | 潜在矩阵表示什么 | 答案／推理轨迹／结构化状态／混合 | A10 的重构、条件生成、修复和 OOD 结果 |
| Q02 | 状态如何初始化 | 先采样一个块／条件初始化器等 | 无答案泄漏；初始成本；闭环稳定性 |
| Q03 | 目标如何分块与压缩 | 可学习槽查询池化／局部分块再池化 | 信息容量、重构质量、可变长度与采样难度 |
| Q04 | 全局上下文如何读取 | 全量 cross-attention／块摘要／top-k 检索 | A4 的一致性、延迟和显存对照 |
| Q05 | 首选连续生成路径 | DDPM／Flow 与不同采样器 | A9 在相同预算下的结果 |
| Q06 | 是否复用预训练 Decoder | 从零训练／预训练初始化 | 机制验证与开放语言任务各自收益；矩阵依赖 |
| Q07 | tokenizer、层数、隐层与共享策略 | 原稿范围内搜索 | 参数计数、词表成本、表达和性能测试 |
| Q08 | 操作预算与损失权重 | 固定／调度／学习策略 | 停止校准、质量—成本曲线及失败模式 |
| Q09 | 阶段验收的数值门槛 | 预先设定最小收益、成本上限和统计规则 | 预实验方差、任务难度、预算与复现需求 |

原稿相关工作随[完整设计](technical-design.md)保留。新颖性不能仅基于“块扩散”“潜在扩散”“动态长度”或“编辑”单个概念，需要对最接近工作逐项核验并以联合机制的对照结果证明。

## 后续变更模板

每次改变以上决策时记录：

- 决策 ID、日期和状态：提议／采纳／废弃。
- 变更后的行为与适用范围。
- 候选方案、关键取舍及所依赖的实验记录。
- 对 checkpoint、latent 缓存、配置、评测与文档的兼容性影响。

不要仅把旧结论删去；保留失效原因，便于追溯实验口径。
